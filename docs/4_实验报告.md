## 4.1 系统设计

### 1) 总体架构

最终系统可以按“硬件抽象层 BSP + 内核 Kernel + 实验 Demo/可观测命令”三层划分：

-   **BSP（`src/bsp/`）**
    -   串口输出/输入、异常向量、中断初始化、定时器初始化、MMU/缓存等基础设施。
-   **Kernel（`src/kernel/`）**
    -   `task/`：任务创建、READY 队列管理、任务信息观测接口
    -   `sched/`：单核调度器（优先级抢占式）
    -   `tick/`：Tick 中断与系统计时
    -   `sem/`：信号量同步原语 + 优先级继承扩展 + semstat 统计
    -   `shell/`：Shell 任务、命令解析与命令集注册
-   **Demo（位于 `src/` 根目录的独立模块）**
    -   `ipc_ring_demo.c`：生产者-消费者 + ring buffer + 信号量同步 demo（`ipc/ipcs` 命令驱动）
    -   `test_priority_inversion.c`：优先级反转 + 优先级继承演示（`demo` 命令驱动）

### 2) 设计目标与原则

1.  **Shell 作为统一入口**：所有扩展功能（观测、演示）均通过 Shell 命令触发，避免 `main.c` 里硬编码 demo 流程。
2.  **可扩展命令框架**：新增命令只需要“实现 handler + 注册到命令表”，不修改 Shell 主循环。
3.  **同步机制可验证**：通过 `ipc/ipcs` 演示信号量在并发任务中的实际使用效果。
4.  **调度问题可演示**：通过 `demo` 演示优先级反转，并用优先级继承机制缓解问题。

### 4.2.2 调度器实现：`schedule()` 对应的内核函数

本工程中“调度”的核心等价于以下函数链路：

-   **选择最高优先级任务**：`OsTskHighestSet()`（`src/include/prt_task_external.h`）
    
    -   遍历 `g_runQueue`，选取 `priority` 最小任务为 `g_highestTask`。
-   **触发调度请求**：`OsTskSchedule()`（`src/kernel/sched/prt_sched_single.c`）
    
    -   若 `g_highestTask != RUNNING_TASK` 且未锁调度（`g_uniTaskLock == 0`），置位 `OS_FLG_TSK_REQ`；
    -   在非中断上下文下通过 `OsTaskTrap()` 进入切换。
-   **真正切换**：`OsMainSchedule()`（`src/kernel/sched/prt_sched_single.c`）
    
    -   检查 `OS_FLG_TSK_REQ` 标志；
    -   更新 `RUNNING_TASK` 与任务状态位；
    -   `OsTskContextLoad()` 恢复新任务上下文。

此外还有一条常用“快路径”：

-   `OsTskScheduleFastPs(intSave)`（`src/kernel/task/prt_task.c`）：用于信号量 pend/post 等路径，在保存/恢复中断状态的前提下尽快完成切换请求。

**从 Original 到当前版本的演进点**：

-   调度主干保持稳定（优先级扫描 + 请求标志 + trap 切换）。
-   为支持“优先级继承”，TCB 增加了 `originalPriority`，并在任务创建时初始化（见 4.2.4）。

### 4.2.3 Shell 实现：`shell_exec()` 对应的内核函数

本工程中“执行命令”的核心等价于：

-   `ShellTask()`：负责读取输入、编辑（回显/退格）、回车提交（`src/kernel/shell/shmsg.c`）
-   `ShellDispatchCmd()`：负责解析与分发（同文件）

**关键实现点：**

1.  **输入同步模型**：UART ISR 投递 `sem_uart_rx`，Shell 任务 `PRT_SemPend()` 阻塞等待字符。
2.  **行编辑**：
    -   可打印字符写入 `cmdBuf` 并回显；
    -   `DEL(0x7F)`/`b` 做退格处理（输出 `b b` 覆盖）。
3.  **命令解析**：提取第一个 token 作为命令名，剩余作为 `args`（目前大多数命令不使用参数）。
4.  **命令注册**：`g_shellCmds[]`（命令名/说明/函数指针），新增命令只需注册一行即可。

**从 Original 到当前版本的演进点（最显著）**：

-   Original 版本仅在 Shell 主循环中硬编码判断 `top/tick`；
-   当前版本升级为“命令表 + 分发器”，并扩展为完整命令集：
    -   `help/ps/top/tick/memstat/semstat/quit`
    -   `ipc/ipcs`（IPC demo）
    -   `demo`（优先级继承 demo）

### 4.2.4 信号量与优先级继承：从同步原语到调度问题修复

#### 1) 信号量基本路径

-   `PRT_SemPend()`：计数足够则直接占用；否则将任务挂入等待队列并触发调度（`src/kernel/sem/prt_sem.c`）
-   `PRT_SemPost()`：若存在等待者，唤醒一个任务并触发调度；否则计数加一并清空 owner

#### 2) 优先级继承机制（本次集成关键点）

为解决“优先级反转”，在 `src/kernel/sem/prt_sem.c` 中加入：

-   `OsPriorityInherit(sem, waiterTask)`
    
    -   若信号量有持有者（owner），且等待者优先级更高（数值更小），则把持有者优先级提升到等待者级别；
    -   若持有者在 READY 队列中，需要从队列移除并按新优先级重新入队（确保调度器能正确选中）。
-   `OsPriorityRestore(sem)`
    
    -   释放信号量时恢复持有者原始优先级；
    -   若等待队列中仍有更高优先级等待者，则持有者继续保持继承后的更高优先级（直到不再需要）。

配套结构：

-   `struct TagTskCb.originalPriority`（`src/include/prt_task_external.h`）
-   任务创建初始化：`taskCb->originalPriority = initParam->taskPrio`（`src/kernel/task/prt_task_init.c`）

### 4.2.5 IPC Demo：ring buffer + 生产者消费者

IPC demo 被封装为独立模块：

-   接口与统计结构：`src/include/ipc_ring_demo.h`
-   实现：`src/ipc_ring_demo.c`

Shell 触发方式：

-   `ipc`：`IPC_RingDemoStart()` 创建 3 个信号量（empty/full/mutex）与 4 个任务（2 Producer + 2 Consumer）
-   `ipcs`：`IPC_RingDemoGetStats()` 读取 ring buffer 统计（在 mutex 保护下），并打印快照

设计点：

-   Demo 与 Shell 解耦：demo 逻辑不侵入 `main.c`，而是被 Shell 命令按需启动；
-   Demo 与信号量解耦：同步完全依赖内核信号量 API，便于向助教展示“OS 原语的可用性”。

## 4.3 问题解决（整合期常见问题与解决方案）

以下问题来自两部分：  
（1）本次合并/集成中典型会遇到的接口与构建问题；（2）你在整合过程中已遇到的问题清单（已在此融合并给出解决方案）。

### 问题 1：交叉编译器路径无效（CMake 找不到编译器）

-   **现象**：CMake 配置时报错 `CMAKE_C_COMPILER ... not found` 或找不到 `aarch64-none-elf-gcc`。
-   **原因**：`src/CMakeLists.txt` 中 `TOOLCHAIN_PATH` 未指向本机实际安装目录。
-   **解决**：
    1.  在本机确认 `aarch64-none-elf-gcc` 实际路径；
    2.  修改 `src/CMakeLists.txt` 中 `set(TOOLCHAIN_PATH "...")`；
    3.  清理 `build/` 重新生成。

### 问题 2：链接错误（Shell 调用的函数未定义）

-   **现象**：链接阶段报错 “undefined reference to `OsDisplaySemStat`/`OsDisplayMemStat` …”
-   **原因**：
    -   Shell 命令已经注册/调用，但对应实现文件未加入编译；
    -   或函数仅声明 `extern`，未提供定义。
-   **解决（按最终版本做法）**：
    -   `semstat`：新增 `src/kernel/sem/prt_sem_stat.c` 提供 `OsDisplaySemStat()`；
    -   并在 `src/kernel/sem/CMakeLists.txt` 中把 `prt_sem_stat.c` 加入 `SRCS`；
    -   `memstat`：最终版本直接在 `src/kernel/shell/shmsg.c` 内基于链接脚本符号实现，避免额外跨模块依赖。

### 问题 3：函数重复定义（重复实现导致编译报错）

-   **现象**：编译时报 `redefinition of 'ShellCmd_MemStat'` / `ShellCmd_SemStat` 等。
-   **原因**：多人合并时把同名命令实现保留了多份（或把 demo 代码拷贝进多个文件）。
-   **解决**：
    -   明确“命令实现的单一归属”：统一放在 `src/kernel/shell/shmsg.c`；
    -   命令注册只保留一份 `g_shellCmds[]`；
    -   删除或重命名重复实现，保证链接符号唯一。

### 问题 4：Shell 无法正确输入或回显（交互体验异常）

-   **现象**：字符不回显、退格无效、回车后命令解析异常。
-   **原因**：Shell 主循环对字符类型处理不完整（例如未区分可打印字符/控制字符，未对 `b`/`0x7F` 做退格逻辑）。
-   **解决（按最终版本做法）**：
    -   对可打印字符做回显与缓冲写入；
    -   对 `b`/`0x7F` 做退格擦除（输出 `b b`）；
    -   对 `r`/`n` 统一作为提交符号，提交前补 `0` 终止字符串。

### 问题 5：跨模块接口适配（头文件/extern/编译单元缺失）

-   **现象**：编译通过但运行异常，或出现隐式声明/类型不匹配警告。
-   **原因**：合并时新增模块（如 `ipc_ring_demo.c`、`test_priority_inversion.c`）未提供统一头文件或未被正确 include。
-   **解决**：
    -   IPC 模块：提供 `src/include/ipc_ring_demo.h` 并由 Shell include；
    -   Demo 入口：在 Shell 中 `extern U32 CreatePriorityInversionDemo(void);` 明确函数原型；
    -   构建系统：在 `src/CMakeLists.txt` 中将新增 `.c` 文件纳入编译目标。

## 4.4 总结（集成式 OS 实验的经验）

1.  **把“功能”变成“命令”**：用 Shell 把调试/演示能力标准化，是课程实验最有效的展示方式之一。
2.  **模块边界要清晰**：核心逻辑放内核模块（task/sched/sem），演示逻辑放独立 demo 文件，Shell 只负责“触发 + 打印”。
3.  **构建系统同等重要**：很多集成失败不是代码错，而是 CMake/链接列表漏文件、漏 include 路径。
4.  **可观测性决定可验收性**：`ps/top/tick/memstat/semstat/ipcs` 把“内核内部状态”搬到终端，是验收时的硬通货。
5.  **优先级继承是很好的加分点**：它把“同步原语”与“调度器行为”联系起来，能清晰解释优先级反转问题及解决方案。
