## 1.2 优先级调度如何工作

本实验内核的调度策略可以概括为：**基于优先级的抢占式调度（数值越小优先级越高）**，并通过“就绪队列 + 最高优先级扫描”确定下一次运行任务。

### 1) 核心数据结构：TCB + 就绪队列

-   **任务控制块（TCB）**：`src/include/prt_task_external.h` 中的 `struct TagTskCb`。
    -   `priority`：运行优先级（数值越小越高）。
    -   `originalPriority`：本次集成新增，用于优先级继承恢复（见 1.4）。
-   **就绪队列**：`g_runQueue`（`struct TagOsRunQue`，在本工程中被简化为链表）。
    -   任务变为 READY 时加入 `g_runQueue`，阻塞/退出时从 `g_runQueue` 移除。
    -   加入/移除入口在 `src/kernel/task/prt_task.c`：`OsTskReadyAdd()` / `OsTskReadyDel()`。

### 2) “最高优先级任务”计算：线性扫描

`src/include/prt_task_external.h` 中 `OsTskHighestSet()` 会遍历 `g_runQueue`，选取 `priority` 最小的任务作为 `g_highestTask`。

这是一种 **O(n) 扫描**的实现，结构简单、便于课程实验验证；在任务数较大时可扩展为“多级位图/优先级链表”等更高效结构。

### 3) 调度触发与切换路径

调度的关键入口（逻辑视角）：

1.  **触发调度请求**：`src/kernel/sched/prt_sched_single.c` 的 `OsTskSchedule()`
    
    -   更新 `g_highestTask`；
    -   若发现 `g_highestTask != RUNNING_TASK` 且 `g_uniTaskLock == 0`，置位 `UNI_FLAG |= OS_FLG_TSK_REQ`；
    -   若当前不在中断上下文（`OS_INT_INACTIVE`），直接 `OsTaskTrap()` 进入切换流程。
2.  **快速路径**：`src/kernel/task/prt_task.c` 的 `OsTskScheduleFastPs()`
    
    -   用于“已经保存中断状态的场景”，例如信号量 pend/post 内部；
    -   逻辑与 `OsTskSchedule()` 类似，但通过 `OsTaskTrapFastPs(intSave)` 走更轻量路径。
3.  **真正切换**：`src/kernel/sched/prt_sched_single.c` 的 `OsMainSchedule()`
    
    -   检查 `OS_FLG_TSK_REQ` 标志；
    -   清标志、更新 `RUNNING_TASK` 与 `g_highestTask` 的状态位；
    -   `OsTskContextLoad()` 恢复新任务上下文。

### 4) Tick 的作用

`src/kernel/tick/prt_tick.c` 的 `OsTickDispatcher()` 在每次 Tick 中断到来时：

-   `g_uniTicks++`：提供系统“时间基准”；
-   重装定时器周期寄存器，维持周期中断。

> 说明：当前代码中 **Tick 主要用于计时/观测**（`tick` 命令展示），未实现显式的 RR 时间片轮转逻辑；调度切换主要由“任务状态变化/同步原语唤醒/显式调度点”触发。

## 1.3 Shell 命令解析如何工作

最终版本 Shell 的实现目标是：**可扩展、模块化、易注册新命令**，并具备基础交互体验（回显、退格、未知命令提示）。

### 1) 输入模型：UART 中断 + 信号量同步 + 环形缓冲区

Shell 任务在 `src/kernel/shell/shmsg.c` 的 `ShellTask()` 中循环：

1.  打印提示符 `miniEuler #`；
2.  通过 `PRT_SemPend(sem_uart_rx, OS_WAIT_FOREVER)` 阻塞等待 UART 收到字符（由 UART ISR 投递信号量）；
3.  从 `ShellCB.shellBuf` 读取字符并处理：
    -   可打印字符：回显并写入本地命令缓冲 `cmdBuf`；
    -   退格（DEL 或 `b`）：回退并“`b b`”视觉擦除；
    -   回车/换行：结束本次输入并进入命令分发。

### 2) 命令分发：命令表 + 函数指针

`ShellDispatchCmd()` 实现了清晰的两步解析：

1.  **提取命令名**：取输入串第一个 token（遇到空格结束），写入 `cmd[16]`；
2.  **定位处理函数**：遍历 `g_shellCmds[]`（命令表），字符串相等则调用对应 `handler(args)`。

这使得新增命令只需：

-   实现一个 `ShellCmd_xxx(const char *args)`；
-   在 `g_shellCmds[]` 添加一行 `{ "name", "help", ShellCmd_xxx }`；

即可自动被 `help` 命令列出，且不需要改动 Shell 主循环逻辑。

## 1.4 创新点总结

1.  **Shell 从硬编码升级为可扩展命令框架**：  
    Original 仅支持 `top/tick` 且靠 `if(cmd[0]=='t'...)` 判断；最终版本改为命令表/分发器，易扩展易维护。
    
2.  **系统可观测性增强**：  
    通过 `ps/top/tick/memstat/semstat` 等命令，在 QEMU 终端下直接观测任务/时间/内存布局/信号量状态。
    
3.  **优先级继承（Priority Inheritance）机制引入**：  
    在 `PRT_SemPend/PRT_SemPost` 路径挂钩继承/恢复逻辑，解决“低优先级持有资源导致高优先级被间接阻塞”的经典问题，并提供 `demo` 可重复验证。
    
4.  **IPC 并发 demo 工程化集成**：  
    将“生产者-消费者 + ring buffer + 信号量同步”封装为独立模块 `ipc_ring_demo.c`，通过 Shell 命令触发与查看统计（`ipc/ipcs`），实现“可演示、可观测、可复现”。
