# 2. 分工与整合报告

## 2.1 模块映射（A/B/C）

### 模块 A（调度器）：TCB 修改、Tick 逻辑、优先级调度链路

**目标**：支撑内核任务的创建/就绪/切换，提供优先级抢占式调度的运行基础，并为同步机制扩展保留必要的 TCB 字段。

**关键文件与职责：**

-   `src/include/prt_task_external.h`
    
    -   定义 `struct TagTskCb`（任务控制块）。
    -   本次集成新增 `originalPriority` 字段，用于优先级继承的“恢复点”。
    -   提供 `OsTskHighestSet()`：扫描 `g_runQueue` 选取 `g_highestTask`（优先级最小者）。
-   `src/kernel/task/prt_task_init.c`
    
    -   任务创建时的 TCB 初始化：`OsTskCreateTcbInit()`。
    -   本次集成补齐 `taskCb->originalPriority = initParam->taskPrio`，保证继承/恢复逻辑一致。
    -   系统启动阶段初始化 RUNNING_TASK、就绪队列等（为调度器提供初始状态）。
-   `src/kernel/task/prt_task.c`
    
    -   READY 队列操作：`OsTskReadyAdd()` / `OsTskReadyDel()`。
    -   快速调度入口：`OsTskScheduleFastPs()`（常用于同步原语内部）。
    -   任务信息输出：`OsDisplayTasksInfo()`（Shell `ps/top` 依赖）。
-   `src/kernel/sched/prt_sched_single.c`
    
    -   调度入口：`OsTskSchedule()`（计算最高优先级并触发切换请求）。
    -   切换主入口：`OsMainSchedule()`（在 trap/调度点完成上下文切换）。
    -   首次切换：`OsFirstTimeSwitch()`。
-   `src/kernel/tick/prt_tick.c`
    
    -   Tick 中断处理：`OsTickDispatcher()`，维护 `g_uniTicks` 并重装定时器周期。
    -   `PRT_TickGetCount()`/`OsDisplayCurTick()` 为 `tick` 命令提供观测。

> 说明：当前实现以“优先级 + 事件驱动调度点”为主，Tick 主要提供节拍与计时观测；若需要“时间片轮转”，可在 Tick 中断或任务运行计数处引入时间片递减与强制调度。

### 模块 B（Shell）：命令注册、解析与调试命令集

**目标**：提供 QEMU `-nographic` 下的交互入口，形成可扩展的“命令表 + 分发器”，并将内核关键观测能力封装为命令。

**关键文件与职责：**

-   `src/include/prt_shell.h`
    
    -   定义 `ShellCB` 与 `SHELL_SHOW_MAX_LEN` 等输入缓冲相关结构。
-   `src/kernel/shell/shmsg.c`
    
    -   Shell 任务：`ShellTask()`（UART 输入、回显、退格、回车提交）。
    -   命令分发：`ShellDispatchCmd()`（tokenize + command-table match）。
    -   命令注册表：`g_shellCmds[]`（新增命令只需注册一行）。
    -   内建命令：`help/ps/top/tick/memstat/semstat/ipc/ipcs/demo/quit`。

**Shell 与内核模块的接口边界：**

-   Shell 不直接操作底层结构，统一通过已导出的函数接口获取信息或触发 demo：
    -   `OsDisplayTasksInfo()`（ps/top）
    -   `OsDisplayCurTick()`（tick）
    -   链接脚本符号（memstat）
    -   `OsDisplaySemStat()`（semstat）
    -   `IPC_RingDemoStart()` / `IPC_RingDemoGetStats()`（ipc/ipcs）
    -   `CreatePriorityInversionDemo()`（demo）

### 模块 C（IPC）：信号量、Ring Buffer、生产者消费者 Demo

**目标**：提供可复用的同步原语（信号量）与可演示的并发 demo（生产者-消费者 + ring buffer），同时补齐“优先级继承”以解决优先级反转问题。

**关键文件与职责：**

-   `src/kernel/sem/prt_sem.c`
    
    -   信号量 P/V：`PRT_SemPend()` / `PRT_SemPost()`。
    -   本次集成新增：
        -   `OsPriorityInherit()`：当高优先级任务阻塞在某信号量上时，提升持有者优先级。
        -   `OsPriorityRestore()`：释放信号量后恢复持有者优先级（或维持到剩余等待者的最高优先级）。
    -   继承/恢复挂钩点：
        -   `OsSemPendListPut()`：任务进入等待队列后触发继承检查。
        -   `PRT_SemPost()`：唤醒/释放路径触发恢复检查。
-   `src/kernel/sem/prt_sem_init.c`
    
    -   信号量池初始化、`PRT_SemCreate()` 等基础设施。
-   `src/kernel/sem/prt_sem_stat.c`
    
    -   信号量状态遍历与打印：`OsDisplaySemStat()`，用于 Shell `semstat`。
-   `src/include/ipc_ring_demo.h` + `src/ipc_ring_demo.c`
    
    -   `IPC_RingDemoStart()`：创建 `empty/full/mutex` 三个信号量并启动 2 Producer + 2 Consumer 任务。
    -   `IPC_RingDemoGetStats()`：加互斥读取 ring buffer 与统计信息，供 Shell `ipcs` 输出。
-   `src/test_priority_inversion.c`
    
    -   `CreatePriorityInversionDemo()`：构造 Low/High/Mid 三任务与共享信号量，触发优先级反转场景；
    -   运行期间会打印 `PriorityInherit/PriorityRestore` 相关日志，验证机制生效。

## 2.2 整合逻辑：系统如何在初始化与运行期串联

### 1) 启动阶段：`main.c` 串联顺序

最终版本 `src/main.c` 的整体职责保持“干净”：

1.  `OsHwiInit()`：初始化中断控制器（GIC）。
2.  `CoreTimerInit()`：启动定时器，为 Tick 中断提供周期源。
3.  `OsTskInit()`：初始化任务管理与调度相关结构（就绪队列、idle 等）。
4.  `OsSemInit()`：初始化信号量模块（分配/管理 sem 控制块）。
5.  `PRT_UartInit()`：初始化串口，提供 Shell 输入输出通道。
6.  `ShellTaskInit(&g_shellCB)`：创建 Shell 任务（优先级 9）。
7.  `OsActivate()`：启动调度，进入多任务运行。

> 设计点：`main.c` 不直接“跑 demo”，而是把 demo 作为 Shell 命令触发，从而让系统保持“可交互 + 可重复演示”的实验形态。

### 2) 运行阶段：三个模块的交互路径

-   **Shell 与输入**：UART ISR → 投递 `sem_uart_rx` → `ShellTask()` 读取字符并解析命令。
-   **调度器驱动运行**：任务创建/唤醒/阻塞会触发调度点（`OsTskSchedule/OsTskScheduleFastPs`），由调度器选择最高优先级任务执行。
-   **IPC demo（ipc/ipcs）**：
    -   `ipc`：创建同步原语与并发任务，生产/消费过程在终端输出；
    -   `ipcs`：读取并打印 ring buffer 状态与统计信息。
-   **优先级继承 demo（demo）**：
    -   `demo`：构造优先级反转场景；
    -   当 High 等待 Low 持有的资源时，`prt_sem.c` 的继承逻辑会提升 Low 的优先级，减少 High 等待时间，并打印继承/恢复日志。
